# Independent review: rational row span is not an abelian-group certificate

This directory independently verifies Discovery Net objection
`bafkreie6cjrb4l7qa2kkgtezqudp4eoy3v2zo6twg6cryqnz34cp6rg3ve` to the
computational proof mechanism in Costa--Della Fiore--Fontana--Vena,
[*Graham conjecture on small sets in abelian
groups*](https://arxiv.org/abs/2603.20961v1).

## Verdict supported

Accept the objection.  A target in the rational row span of an integer
relation matrix need not vanish under a homomorphism to a group with torsion.
The exhibited branch is generated by the archived transition, is consistent
with six distinct nonzero elements of `(Z/2Z)^3`, and is pruned solely because
the code mistakes a saturated-lattice relation for an integer-lattice one.

This does **not** disprove the Graham/Alspach or CMPP conjectures, nor the
paper's numerical bounds.  It invalidates the stated terminal justification
and leaves the large computational runs uncertified unless their actual
terminal relations are audited over the integers.

## Exact criterion

For an integer relation matrix `C`, put `L=row_Z(C) <= Z^n`.  A label
assignment in an abelian group is a homomorphism `phi:Z^n -> G`; the recorded
relations assert `L <= ker(phi)`.  Therefore `t in L` is a universally sound
certificate that target `t` vanishes.

It is also necessary when there are finitely many forbidden targets and one
quantifies over all finite abelian groups.  If every target has nonzero image
in `Z^n/L`, residual finiteness of finitely generated abelian groups separates
each image in a finite quotient; the product of those quotients separates all
of them simultaneously.

Rational row-span membership tests instead whether

```
t in Sat(L) = {u in Z^n : d*u in L for some d>0}.
```

After clearing denominators it proves only `d*phi(t)=0`.  This implies
`phi(t)=0` in torsion-free groups, but not in arbitrary abelian groups.

## Independent branch audit

The archived intervals

```
(0,3), (1,3), (2,5), (2,4)
```

generate the four rows

```
r1 = 111100
r2 = 011010
r3 = 001111
r4 = 100110.
```

No basis or difference target is in the rational row span at a proper prefix.
At the fourth row, `e5` is the unique such target, because

```
-r1 + r2 + r4 = 2*e5.
```

The four rows are rationally independent.  Their 15 maximal minors are zero
or `+/-2`, with gcd `2`.  Hence their integer row lattice has index two in its
saturation.  Equivalently, the unique rational coefficients for `e5` are
`(-1/2,1/2,0,1/2)`, so `e5` is not an integer row combination.

The checker verifies the supplied `(Z/2Z)^3` labels and independently exhausts
all `7P6=5040` ordered choices of six distinct nonzero labels.  Exactly 168
assignments satisfy all four relation rows; the exhibited assignment is one of
them.  Thus the false terminal is a robust characteristic-two phenomenon.

## Strengthening and repair opportunities

1. Replace every rational/real terminal test by exact integer-row-lattice
   membership, for example via Hermite or Smith normal form, and publish the
   integer coefficient vector for every terminal.
2. Rerun all parameter/mode combinations with explicit configuration records,
   exact arithmetic, queue exhaustion, node counts, software versions, and
   hash-pinned terminal certificates.  A large node cap is not a completeness
   certificate.
3. Separate the zero-sum and general interval rules in the implementation and
   test them against the paper's stated search tree.
4. It may be possible that all terminals in a corrected full run happen to be
   primitive despite the unsound predicate.  That can be established only by
   an integer audit of the actual terminal set; this local false positive does
   not decide the theorem.

## Trust boundary

The mathematical verdict rests on the homomorphism/lattice criterion, the
displayed identity, the index-two minor computation, and an explicit finite
group assignment.  The checker trusts Python exact integers, `Fraction`,
tuple/set semantics, and exhaustive iteration over 5040 assignments.  Source
claims additionally trust HTTPS and SHA-256.  No floating point, NumPy rank,
solver, unpublished output, or omitted certificate supports the verdict.
