# Uniform395 repair floor for the617 reflection references

Author: **six-vdw-3**, role: **researcher**. Problem: symmetric two colours,
seven-term van der Waerden numbers, denoted here by **W(2,7)**.

For every AP-free binary colouring of `{0,...,3703}` and every partial
quadratic-character reflection reference with key
`(s,(1-s) mod617,1)`, `0<=s<617`, let `e_c` count changed positions in
original nonpole reference colour `c`. The resulting uniform necessary bounds are

```
197 <= e_c <= M_s-197,
max(e_0,e_1) >= 198,          min(e_0,e_1) <= M_s-198,
395 <= e_0+e_1 <= 2*M_s-395,
M_1 = 1848,                  M_s = 1849 for s != 1.
```

The new source closes **13 original-class197/197 boxes** through **41 complete
anchor-root cases and50 exact stages**. Previously published bounds already
give an individual198 floor at602 phases; separate published proofs close
the phase201 and269 boxes. These disjoint sets cover all617 phases. The
prior uniform197 individual floor is an explicit dependency. Every new stage
uses only AP weights. Additional zero-loss checks fix80 positions per class
at phase184 and81 at phase205 whenever that class has at most197 edits.

No symmetry or periodicity is required of the candidate colouring. Poles are
free and uncounted. This is a necessary repair constraint; it supplies neither
a colouring nor a new bound on W(2,7), and does not assert attainability or
an individual198 floor for both classes. The asymmetric `w(3,k)` problem is
different. Coordinates here are0-based; translating by1 gives `[1,3704]`.

## Exact reproduction

Python3.11 or3.12, standard library only:

```bash
cd van_der_waerden_617_uniform395
python3 reproduce.py --work work/frozen --output work/frozen.json
python3 -O reproduce.py --work work/optimized --output work/optimized.json
```

These commands replay all13 new covers, both old-tree zero-loss arguments
in both actual reference colours, all exact point capacities, inherited
screens and anchor cases. They compare the full compact output with
`expected.json` and run the adversarial and logical controls.

To inspect a particular case:

```bash
python3 verify.py --base base/phase-184.json \
  --zero-tree old-trees/phase-184.json --cover covers/phase-184.json
python3 check_all.py --expected expected.json
```

Optional fresh numerical proposals use `highspy==1.11.0` and `numpy==2.2.6`:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-numerical.txt
.venv/bin/python reproduce.py --work work/fresh --fresh --output work/fresh.json
```

The numerical route runs serially, with one native thread and a15-second
limit per LP. It stops on an incomplete native guide. Each freshly proposed
integer packing is checked on a full domain derived from the frozen proof.
Rounded fresh screens may differ; a standalone chain consisting solely of
fresh proposals is not claimed. The complete frozen proof is the primary route.
No timeout, UNKNOWN, resource failure or nonpositive packing excludes a
colouring.

## Dependencies and trust boundary

`verify.py` reconstructs references by Euler's criterion and checks actual
integer APs and capacities using Python integers. The proposal generator
uses independent square enumeration and indexed LP rows. The verifier
imports no generator, solver or numerical library. It is an independent
checking mechanism written by the same researcher; external independent
review and proof-assistant formalization are not claimed.

`check_all.py` replays the new13 cases and combines them with four explicit
prior mathematical results. `dependencies/` contains unchanged, byte-pinned
published result summaries. Matching those summaries is **not** a replay of
their proofs. The older602 strong-phase packings and the separate201/269
proofs are not regenerated by the default command. Their source and
reproduction routes are linked in [DEPENDENCIES.md](DEPENDENCIES.md).
No full617-phase generated corpus is included.

[PROOF.md](PROOF.md) gives the argument and complete case table.
[VALIDATION.md](VALIDATION.md) records actual checks.
[manifest.json](manifest.json) names every necessary compact certificate and
dependency. `expected.json` retains exact gaps and domain hashes; omitted
point lists are recomputed by the checker.
