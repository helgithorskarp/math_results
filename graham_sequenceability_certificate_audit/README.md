# Integer-lattice obstruction to the published Graham-sequenceability search

## Result and scope

Costa, Della Fiore, Fontana, and Vena state new small-cardinality cases of the
Graham/Alspach and CMPP sequenceability conjectures for arbitrary abelian
groups in [arXiv:2603.20961v1](https://arxiv.org/abs/2603.20961).  Their
Section 3 search records integer relations among labels and declares a branch
contradictory when a forbidden target is in the row span over the rationals
(implemented by floating-point NumPy rank).  This criterion is not sound for
abelian groups with torsion.

This directory establishes two things exactly:

1. the correct universal certificate is **integer-row-lattice membership**,
   not rational-row-span membership; and
2. a four-relation branch generated by the archived tree transition is a
   concrete false positive for the rational test.  Six pairwise distinct,
   nonzero labels in `(Z/2Z)^3` satisfy every recorded relation, although the
   rational test declares that the fifth label is zero.

This is an objection to the published computational proof mechanism and its
reproducibility, not a counterexample to any sequenceability conjecture or to
Theorems 1.4--1.6 themselves.  The explicit branch uses the zero/equality
targets with `initial_cons=[]`.  It proves that the paper's stated terminal
certificate justification is false and that the archived computation cannot
be accepted as an arbitrary-abelian-group proof without an additional audit
showing that every terminal used in the claimed compression runs has an
integer-lattice certificate.

## Exact certificate criterion

Let `C` be an integer matrix whose rows encode the relations already assumed
on a branch, let

```text
L = row_Z(C) <= Z^n,
```

and let `T` be the finite set of forbidden targets: basis vectors, differences
of basis vectors, and any compression vectors.  A label assignment in an
abelian group is a homomorphism `phi: Z^n -> G`; the recorded relations say
`L <= ker(phi)`.  Then

> Every assignment in every finite abelian group satisfying the recorded
> relations makes at least one target in `T` zero if and only if `T` intersects
> `L`.

The forward implication of `T intersect L != empty` is immediate.  Conversely,
if every target remains outside `L`, its image is nonzero in the finitely
generated abelian group `Z^n/L`.  Finitely generated abelian groups are
residually finite.  For each of the finitely many target images choose a finite
quotient in which it remains nonzero, and take the product of these quotients.
This gives one finite abelian assignment satisfying all recorded relations in
which every target is nonzero.

By contrast, rational membership tests whether a target is in the saturation

```text
Sat(L) = {u in Z^n : d*u is in L for some positive integer d}.
```

It only proves that a multiple of the purportedly forbidden group element is
zero.  That is not a contradiction in a torsion group.

## Concrete false-positive branch

The four accumulated rows are

```text
r1 = (1,1,1,1,0,0)
r2 = (0,1,1,0,1,0)
r3 = (0,0,1,1,1,1)
r4 = (1,0,0,1,1,0).
```

They are generated from the identity ordering by the archived intervals

```text
(0,3), (1,3), (2,5), (2,4).
```

No proper ancestor is terminal under the code's basis-vector and difference
tests.  At the fourth node,

```text
-r1 + r2 + r4 = 2*e5,
```

so `e5` is in the rational row span and the code reports a zero-element
certificate.  The actual integer consequence is only `2*a5 = 0`.

Now work in `(Z/2Z)^3` and take

```text
a1=110  a2=101  a3=111  a4=100  a5=010  a6=001.
```

These labels are pairwise distinct and nonzero.  The sum selected by each of
`r1,r2,r3,r4` is `000`, while `a5=010` is nonzero.  Thus this is a
definition-level countermodel to the terminal inference.

The exact data are in [certificate.json](certificate.json).  The verifier
reconstructs the branch independently, checks all proper ancestors by exact
`fractions.Fraction` elimination, verifies the integer relation, and checks
the group assignment directly.

## Archived-source audit

The paper cites code DOI
[10.5281/zenodo.18997904](https://doi.org/10.5281/zenodo.18997904).  Its current
version record is
[10.5281/zenodo.18997905](https://doi.org/10.5281/zenodo.18997905), containing
one file, `treeSearch.py`.  The audited file has SHA-256

```text
d3dbceb4728f5cc0614813d4b352ab1000b6b160e068f8cce397629dda19ab91.
```

The hash-pinned audit records four further reproducibility limitations:

- relations are converted to `dtype=float` and tested with
  `numpy.linalg.matrix_rank`, so even rational rank is not certified exactly;
- `generate_children` always enforces `j-i <= n//2`, whereas the paper says
  this restriction is for the zero-sum case and that the general case excludes
  only the full interval;
- the only shipped `full_tree()` configuration sets `n=22`, `sum_zero=0`, and
  uses the non-zero-sum compression targets, although the stated general bound
  is 20 and the zero-sum bound is 22; and
- BFS stops when a node cap is reached, but the returned result contains no
  queue-exhaustion/completeness flag and the main program does not assert
  exhaustion.

No terminal paths, exact row-lattice certificates, run manifest, or claimed
summary output are included in the Zenodo record.  These source facts do not
by themselves show that a particular claimed full run hit an invalid branch;
they show that the archived source does not presently supply a reproducible,
checkable proof of Propositions 4.1 and 4.2.

## Reproduction

Python 3.11 or later is sufficient; only the standard library is used.

```bash
./run_and_check.sh
```

The main certificate verifier ends with

```text
rational_row_span_rule_sound_for_arbitrary_abelian_groups=FALSE
```

`search_false_positive.py` independently performs the deterministic tree
search and rediscovers the same branch.  For `n <= 25`, its
characteristic-zero row-span decisions are exact: it reduces modulo the prime
`2^61-1`, which exceeds the Hadamard bound `n^(n/2)` for every relevant minor.
It then constructs an elementary-abelian countermodel from a nullspace basis.

`audit_archived_source.py` downloads the cited Zenodo file, rejects any hash
change, and reports the exact lines supporting the source audit.  Pass
`--source /path/to/treeSearch.py` for an offline copy of the same file.

## Trust boundary

The mathematical claim uses the elementary homomorphism/lattice argument and
the explicit `(Z/2Z)^3` assignment.  Verification trusts Python's arbitrary
precision integers, `fractions.Fraction`, JSON parser, and runtime.  The source
audit additionally trusts HTTPS retrieval from Zenodo, but pins the received
bytes by SHA-256.  No floating-point arithmetic, NumPy result, solver, or
unpublished run output is used as evidence.
