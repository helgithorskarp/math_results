## Why the finite reduction is complete

Fix the published four-colouring of a host `H` and let `L(p)` be the colours
available at an added point `p`: the colours not used on host neighbours of
`p`.

If `p` has at most two host neighbours, then `|L(p)| >= 2`. If it has at
least three, three of those neighbours lie on the unit circle centred at
`p`. Three distinct points on a circle are noncollinear, so they uniquely
determine `p`. It is therefore enough to enumerate the nonhost centres of
all host triples having unit circumradius. This argument imposes no field or
grid assumption on the arbitrary added point.

A pair of added points is list-colourable unless they are adjacent and both
lists are the same singleton. If either point is outside the finite candidate
set, its list has size at least two. Thus it is sufficient, and not merely
necessary, to check that every candidate list is nonempty and no candidate
unit edge joins equal singleton lists.

For `H_plus`, the exact census found 103,648 unit-circumradius host triples:
93,131 have an existing host vertex as centre and the other 10,517 are
covered, without repetition beyond the expected `binomial(degree,3)`
multiplicity, by exactly 1,420 distinct nonhost candidates. Direct adjacency
reconstruction found 5,710 candidate/host incidences and 3,975 candidate
unit edges. The available-list sizes were 941 singletons, 461 doubletons and
18 tripletons. Of 1,880 edges joining two singleton candidates, zero joined
equal singleton colours. I also checked an explicit allowed colour pair for
all 1,007,490 unordered candidate pairs.

The second embedding is obtained label by label from the first by the exact
ring automorphism `r -> -r`. The checker verifies this map on all 64 products
of basis elements, verifies that it commutes with complex conjugation, and
rebuilds both edge sets. Consequently it preserves the unit-distance graph,
candidate-neighbour structure and the same fixed host colouring.

## Independent computation

I first replayed the submitted primary verifier, its separately implemented
author audit, all controls and all published SHA-256 checks. I then wrote
[`independent_check.py`](independent_check.py), which imports none of the
submitted Python modules. It uses generic quotient-ring monomial reduction
rather than the submitted multiplication routine and screens with a third
prime and roots

```text
p = 5051,  z = 2194,  r = 528.
```

The screen is used only to reject impossible equalities; all 107,256 surviving
triples are decided in exact integer arithmetic. The checker rescans all
21,464,520 host triples, verifies every submitted candidate coordinate and
every host/candidate and candidate/candidate adjacency, proves the exact
triple cover, and reconstructs the list obstruction check. The independent
result is recorded in [`report.json`](report.json).

From the repository root, using Python 3.11 or later and a new work path:

```bash
review_work=/scratch/path/that/does/not/yet/exist
python3 -B hadwiger_nelson_dense506_two_point_extension/verify.py \
  --work "$review_work" > "$review_work.verify.json"
cmp hadwiger_nelson_dense506_two_point_extension/expected.json \
  "$review_work.verify.json"
python3 -B hadwiger_nelson_dense506_two_point_extension/audit.py \
  --work "$review_work" > "$review_work.audit.json"
cmp hadwiger_nelson_dense506_two_point_extension/expected_audit.json \
  "$review_work.audit.json"
python3 -B hadwiger_nelson_dense506_two_point_extension_review1/independent_check.py \
  --source hadwiger_nelson_dense506_two_point_extension \
  --candidate-work "$review_work" \
  --report "$review_work.review1.json"
cmp hadwiger_nelson_dense506_two_point_extension_review1/report.json \
  "$review_work.review1.json"
(cd hadwiger_nelson_dense506_two_point_extension_review1 && sha256sum -c SHA256SUMS)
```

The candidate work directory is generated by the submitted producer, but
the reviewer checker does not trust its contents by hash alone: it decodes
every point, rebuilds all adjacencies, independently rescans the complete
host-triple universe, and checks that the candidate neighbourhood triples
are exactly the external-centre triples.

## Trust boundary and uncertainty

The review imports the pinned raw Parts coordinate tables as data, CPython's
arbitrary-precision integer semantics, and SHA-256 for artifact identity.
It independently checks all algebraic relations and every geometric predicate
used by this theorem; it does not need the source gadgets' advertised forcing
or minimality properties. The finite computations use no floating-point
mathematical decisions. The geometric reduction and checker are ordinary
human-readable mathematics and code, not proof-assistant formalizations, so
implementation and review error remain the residual trust boundary.
