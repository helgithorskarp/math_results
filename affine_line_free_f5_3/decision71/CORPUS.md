# Certificate corpus and preservation

The complete author computation has 109,676 checked UNSAT cases. Its
exact-value claim is **awaiting independent acceptance**. This document
describes the evidence needed to inspect or reproduce that computation;
it is not a review of the theorem.

## What is available

| Artifact | Location and size | What it establishes |
|---|---|---|
| Mathematical reduction and generators | This public directory | An auditable reduction to the complete finite family; see [THEOREM.md](THEOREM.md) |
| `CERTIFICATES.json` | Public, compact | Complete historical input/proof digest coverage, case counts and production checker identities |
| `VALIDATION.json` | Public, compact | Author production and validation results, with their stated scope |
| `orbits.json` | Generated by `verify.py`; 7,220,694 bytes | The fixed, ordered 109,676-case input catalogue |
| Original binary DRAT traces | Preserved in the author workspace; 19,782,097,200 bytes | The derivations checked in the author computation |
| Original CNFs, checker logs and case records | Preserved alongside those traces | Formula bytes and per-case production provenance |

The original large corpus is **not included in GitHub**. This package does
not advertise a public download of it. A reader with only the repository
can regenerate the complete input family and fresh proofs using the
[README commands](README.md). The historical solver traces need not be
reproduced byte for byte: each fresh trace must pass proof checking, and
the regenerated input blocks must match `CERTIFICATES.json`.

The fixed catalogue SHA256 is
`02727db9fb02d60a8597f84329f7376bba2c43422d63241da1c251fde97e4eb2`.
The historical `CERTIFICATES.json` SHA256 is
`ec7fabe454c7a0e6297f3347de038028602a1aae81efd377ff4d938883af31c4`.
This preservation supplement leaves that manifest unchanged.

## Case and digest formats

Index `i` is stored under `iii/case_jjjjjj`, where `iii` is `i // 1000`
padded to three digits and `jjjjjj` is `i` padded to six digits. Its four
files have suffixes `.cnf`, `.drat`, `.check.log`, and `.json`. For example,
case 20,750 has prefix `020/case_020750`.

The record identifies the case, quotient weights, three-hole gauge, 125
point variables, clause count, input-catalogue hash, CNF hash, proof hash
and size, original checker binary hash, solver statistics and timings.
`audit.py` regenerates the CNF, compares its SHA256 to the saved formula,
checks the saved proof hash and size, and reads the historical checker log.
It **does not recheck DRAT derivations**. Its successful result presumes
the separately recorded checker executions; a saved success log is not
itself a proof of UNSAT.

The 112 manifest blocks use half-open intervals. Within each block,
`ordered_cnf_hashes_sha256` hashes the concatenation of the ordered
32-byte CNF digests, and `ordered_proof_hashes_sha256` does the same for
the proof digests. These are binary digest bytes, not ASCII hexadecimal
strings. The original checker counts are 10,504 stock and 99,172 with
the documented allocation patch. The manifest does not hash the original
log or record bytes; a fresh preservation recheck records those identities
separately. No hash or checker-count comparison establishes a proof rule.

## Recheck an existing corpus without replacing its evidence

If the existing corpus is available, use an unmodified DRAT-trim build
from the source pinned in [CHECKER.md](CHECKER.md):

```sh
python3 recheck.py --domain /path/to/orbits.json \
  --proofs /path/to/original-proofs --out /tmp/decision71-stock-recheck \
  --drat-trim /path/to/stock-drat-trim
```

The output directory must not already exist, and it must be disjoint
from the source directory. The command runs no SAT search. It checks
every selected trace afresh, saving new checker logs and new records
only in the new directory. For each case it compares the hashes of all
four original files before and after the checker invocation. It also
checks the original record against the regenerated CNF and compares each
completed input/proof block against the supplied manifest. The default
manifest is the historical `CERTIFICATES.json`; `--manifest` can select
a complete manifest for freshly generated proofs instead.

Success on the whole family requires `recheck.json` with status
`COMPLETE_EXISTING_CORPUS_DRAT_RECHECKED`, `fresh_checks: 109676`,
`reused_acceptances: 0`, and `complete_family: true`. Each fresh checker
must exit zero and emit a complete `s VERIFIED` line. Missing files,
changed bytes, a rejected proof or a mismatched block prevent a successful
range summary. The checker executable is hashed before and after the run.

For a bounded control, append `--start 0 --stop 1000` and choose another
new output directory. Range endpoints must be whole manifest block
boundaries. Such a result has `complete_family: false` and cannot certify
the whole family. There is no implicit resumption: a failed or interrupted
run leaves its new logs for inspection, and another invocation needs a
new output directory. It never silently counts an earlier acceptance as
a fresh check.

The older `replay.py --recheck-existing` command **replaces saved checker
logs and checker identities in place**. Use it only on a disposable
generated copy if that behavior is intended. Use `recheck.py` to preserve
an archival corpus. The historical manifest and production checker counts
must remain identified with the original computation.

Author controls for this new path are reproducible with:

```sh
python3 validate_recheck.py --domain /path/to/orbits.json \
  --proofs /path/to/original-proofs --out /tmp/decision71-recheck-controls \
  --drat-trim /path/to/stock-drat-trim
```

They modify only private copies and test damaged inputs and proofs,
missing evidence, invalid ranges/manifests, output collisions and source
preservation. [RECHECK_VALIDATION.json](RECHECK_VALIDATION.json) records
these controls and one complete 1,000-case digest-block recheck. This is
author validation of the preservation path, not a new full stock replay.

## Remaining trust boundary

Fresh DRAT checking separates the SAT solver's search from proof
validation. It still trusts the chosen DRAT checker, ordinary execution,
the formula semantics, enumeration completeness and written reduction.
The allocation patch is unnecessary when a stock checker is used.
Matching hashes establishes evidence identity, subject to SHA256; it
does not establish mathematical completeness or independent acceptance.
The [review guide](REVIEW_GUIDE.md) separates those obligations. A durable
independent review of the full exact-value argument is still required
for the campaign handoff.
