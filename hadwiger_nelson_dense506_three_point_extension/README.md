# Arbitrary three-point extension for dense506

**Result.** For either pinned506-vertex dense host, its published proper
four-colouring extends after adding **any three arbitrary plane points**.
Every subgraph of such a union is therefore four-colourable. This closes
all deletion repairs using at most three new points for these hosts,
including every resulting graph on at most508 vertices.

The [proof](PROOF.md) combines the preceding non-field closure with a new
complete field-valued circle-intersection census. It is an exact
computer-assisted theorem; external review is pending. There is no new
five-chromatic graph. The result is specific to these two fixed placements
and their fixed colouring.

## What this pass establishes

Every differently coloured host pair is considered:96003 pairs and22887
squared distances. Explicit roots certify184 square distances in
F=Q(sqrt(33),sqrt(-408+72sqrt(33))). The other22703 distances each have
an independently checked finite-field nonsquare witness. Only17 field
maps, using primes17 through131, are needed. The proof explains why
these modular rejections remain sound even if a prospective square root
initially has a denominator divisible by the prime.

The complete intersection set has4523 points:506 in the host,1402 with
at least three host neighbours, and2615 with exactly two neighbours.
Those2615 are the only remaining candidates after the imported
three-addition reduction. Their six neighbour-colour classes have643
unit edges and **no unit triangles**. Thus the necessary obstruction to
extending the fixed colouring never occurs.

A separate audit uses generic eight-basis arithmetic and reconstructs
the other real host embedding from the original Parts tables. It checks
all pair assignments and root decisions, compares all candidate points
and provenance entrywise, and scans2288638 host/point pairs. It then
checks both possible equilateral third points of every relevant unit
edge; all1286 lookups miss. The checker imports neither the producer
nor its square-root code.

These are author-run implementation checks, not an external review of
the new theorem. [validation.json](validation.json) records the trust
boundary and execution measurements.

## Reproduce

Use CPython3.11.2 (tested), with only its standard library. In a full
repository checkout, run the following from this directory. Choose a
fresh external work directory. Do not use Python's optimization flag:
assertions are proof checks. No compiler, native solver or downloaded
large certificate is needed for this pass.

```bash
python3 -B generate.py --work /scratch/fresh-hn-three-point
python3 -B audit.py --work /scratch/fresh-hn-three-point
python3 -B controls.py --work /scratch/fresh-hn-three-point
python3 -B verify.py --work /scratch/fresh-hn-three-point
sha256sum -c SHA256SUMS
```

Expected final message:
`ARBITRARY THREE-POINT EXTENSION: COMPLETE FIELD CENSUS AND AUDIT VERIFIED`.

[expected.json](expected.json) records the complete counts and four
regenerated stream identities. [expected_audit.json](expected_audit.json)
records the independent audit; [expected_controls.json](expected_controls.json)
records1250 known squares, pure-r and zero branches, rational nonsquares,
four circle-intersection boundary cases, a positive equilateral triangle,
and five deliberately corrupted certificates that must be rejected.
The corruptions cover a bad prime, a false nonsquare witness, an altered
square root, an omitted host pair, and an omitted candidate point.
Rejection is checked against the relevant verifier assertion, so an
unrelated import or file error cannot masquerade as successful rejection.

The public producer took14.216 seconds with93,696 KiB peak RSS; the full
independent audit took10.181 seconds with119,384 KiB peak RSS on the
recorded machine. The direct Python prototype was already fast enough:
distance grouping took1.115 seconds and square classification5.046
seconds. No native rewrite or parallel execution was needed. All four
public generated streams matched the prototype byte for byte; the
public audit was then rerun completely after its path and host-membership
cleanup. No further computation remains running.

The point encoding is `(D,x0,x1,x2,x3,y0,y1,y2,y3)`, meaning
`((x0+x1*z+x2*r+x3*z*r)/D, (y0+y1*z+y2*r+y3*z*r)/D)` in the scaled
plane coordinates of the proof. D is positive and coprime to all eight
numerator coefficients together. Distance rows use numerator distances
at the host denominator2592; q is converted to the physical norm before
square testing. Colour masks use `1<<c` for c in{0,1,2,3}.

The diagnostic `kind` labels on distance rows distinguish negative real
q from positive nonsquares using exact field ordering. The theorem and
independent rejection audit use the root or nonsquare certificate;
no claim depends on that diagnostic subdivision. Hashes identify the
streams; completeness is established by the producer and audit, not by
a hash match alone.
